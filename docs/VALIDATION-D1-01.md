# D1-01 验证记录与复现

日期：2026-10-12。候选游戏版本0.2.1，策划基线1.0。此记录只覆盖存档基础工作包，D1完整技能/装备/关卡闭环仍待制作。

## 已验证结果

- `npm run check`：五个运行JS模块语法通过；GLB有效、蒙皮挂接与Idle/Walk/Cast动作资源通过；61项存档测试全部成功，0失败。
- 原0.2.0浏览器基线：模型加载、人物拖动、移动、四技能实际效果、装备加成和刷新恢复通过。
- 0.2.1浏览器回归：旧档完整迁移且旧键原文不变；真实文件下载；导入预览/取消不写存储；确认后替换并回到入场画面；手动旧角色恢复点不被普通保存覆盖；恢复可逆。
- 错误JSON、非法等级、悬空装备引用、重复ID、内容校验错误、未来版本和过大输入均拒绝，既有好档不变。坏主档/未来主档可保留原文后显式恢复或导入好档；仅坏legacy旧档也可原样导出并由合法文件恢复。
- 主档写失败时，持久档原文保持，导出包含未保存装备；解除故障后导入/恢复仍保留当前内存成长。
- 模态打开后战斗暂停；关闭后仅在适当状态恢复。人物/行囊叠层保持暂停，导入关闭人物窗后仍停留入场画面。
- Chromium桌面与390×844触屏视口：双触点摇杆/冰霜、人物窗与存档窗适配、页面无横向溢出，测试未发现pageerror。
- `git diff --check`通过。跨页读/比较/写只实现已知修订冲突检测，未证明完整并发事务；真实手机性能与长期平衡未测试。

## 代码与故障测试

需要Node.js及Python3。本游戏运行无需npm安装依赖。

```sh
npm run check
npm run dev
# 打开 http://localhost:5173
```

旧档样本在 `tests/fixtures/legacy-v0.2.0.json`；保存了7级、123经验、3次通关和两件法杖。样本已装备31伤害法杖，原战斗规则应给法术伤害77、最大生命184。

`tests/save.test.mjs`使用注入存储和时钟验证数据与持久化结果：无效输入零替换；迁移先备份；辅助读取失败不把默认1级覆盖到7级好档；坏legacy可显式导入恢复；损坏恢复点先归档再修复；提交失败保留已有角色/恢复点；当前未成功落盘的成长也能作为手动恢复点。测试通过不等于所有浏览器存储故障已经穷尽。

## 可选浏览器复现

自动化使用临时浏览器上下文，QA仅在HTTP响应中附加只读运行快照，项目源码不加入调试入口。以下工具属于测试依赖，游戏发布资源不包含它们。

```sh
npm install --no-save --package-lock=false playwright-core@1.64.0
npm run dev
# 另一个终端，确保 Chromium 可用：
npm run check:browser
```

`tests/browser-smoke.cjs`默认目标为 `http://127.0.0.1:5173`，Chromium路径默认 `/usr/bin/chromium`。其他环境用 `D1_QA_URL` 与 `D1_CHROMIUM_PATH`指定；截图默认在系统临时目录，也可用 `D1_QA_OUTPUT`指定。支持final、regression、write-failure、invalid-legacy模式；baseline模式用于原0.2.0版本，不是0.2.1的完成标准。

本轮原脚本的各阶段回归已通过；归入仓库后对可移植脚本另跑invalid-legacy场景，验证新路径和加载方式。测试使用Headless Chromium和软件渲染手机视口，不能作为真机帧率、温升或续航结论。

## 人工可重复检查

1. 原浏览器有0.2.0角色时打开新版，查看等级、装备和通关次数；开始游戏并换装、刷新，应继续该角色。
2. 打开存档面板导出当前角色；选择导出的文件，预览后取消，原角色应不变。再确认导入，应回到入场画面。
3. 导入后正常游戏和保存，再打开恢复备份，预览应仍能找到手动替换前的角色；确认恢复后检查装备及成长。
4. 用无效JSON文件导入，应显示原因且角色不变；不应只因为选择了文件就扣除、替换或删除成长。
5. 在人物或行囊暂停状态处理存档，再返回，不应穿过模态继续攻击；导入后应重新进入地窟。

浏览器清除站点数据会删除本机档；跨设备恢复通过导出文件手动完成。没有账号云同步或可信线上经济。后续D1-02从本工作包保存的模块边界继续，不重建已完成策划。
