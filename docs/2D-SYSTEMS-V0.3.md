# 余烬纪事 2D · v0.3 系统扩展交付与验收

版本日期：2026-10-13。核心：从 3 槽装备与单一地牢，扩展成可复玩的单机 ARPG 系统。此为真实运行版本，不是视觉概念图。

## 游戏内容

**装备：13 个可穿戴部位**：头盔、肩甲、胸甲、手套、腰带、腿甲、靴子、主手、副手、护符、戒指 I、戒指 II、遗物。支持自动拾取、背包（80 格）、装备/卸下、分解、装备评分比较、直接生效的面板属性。相同一件戒指不能重复装备两槽。

**掉装**：每部位多个基础物品名称；普通、魔法、稀有、传奇、套装 5 品质。由物品等级决定随机基础属性与词缀范围；随机附加法术强度、生命、法力、护甲、暴击、暴伤、施法速度、火冰增伤、火冰暗影抗性、法力恢复、击中回血、技能等级等词条。按照部位约束可出现的词缀。稀有度高意味着更多可抽取词条位，并非保证必定最强。

**套装**：龙焰法衣 3 件和监牢审判 3 件。2 件、3 件效果有实际数值/战斗反馈；龙焰 3 件触发火系强化，审判三件增加生命与暴击。

**技能**：余烬箭、霜环、冰晶箭、冰甲、陨火、闪现、恢复药剂共 7 项。随着等级解锁，并有技能点可投入（每项最高 8 级），强化技能伤害、冷却、持续时间/位移或生命恢复。技能伤害引用实际装备词缀。主界面增加键盘技能快捷键与触控技能按钮。

**敌人**：近战骷髅/游荡者、远程弓手、瘟疫巨汉、教团术士、洞穴蜘蛛、灰烬司祭首领。首领新增半血阶段增援和扩散弹幕。特殊敌人已有不同速度、体型、攻击距离与远程弹种；系统尚未包含完善的逐帧攻击前摇与全地图路径规划。

**地图：五个区域**：断昼前庭、遗弃监牢、余烬祭坛、渊底裂隙、失名者圣所。区域切换真正影响障碍密度、墙体比例、火把数量、环境叠加视觉层、怪物组成和关卡种子。仍由现有 2D 基础图集构成，暂未实现手工制作用于 A 方向的五套写实斜视场景。

## 兼容与存档

- 沿用原浏览器 localStorage 键 ember-chronicles-2d-v1，以避免旧角色无法找到存档。
- 加载版本 1 存档时转换为 v2 结构，保留旧等级、金币、背包、已装备主手/法袍/护符；新添槽位空置；旧版本升过级的角色可分配对应技能点。
- v2 存档可导出/导入，上传前执行字段有效性检查与装备引用校验。无法兼容高于 v2 的未来格式时重置为新档（建议先备份）。
- 未修改独立的 3D 版本文件与存档。

## 已有的验收与尚存的不足

- 已通过确定性地图、地图碰撞、13 槽装备、法术加成、戒指防重复、套装生效、词缀合法性、掉落采样、v1→v2 存档迁移、技能点不重复等自动化测试。
- 已通过 Chromium PC / 手机视口中的页面加载、真实素材加载、移动、施法、背包 13 槽位、7 技能、区域选择、暂停与恢复流程。
- **A 方向视觉基准尚未达成**：目前实际人物仍然使用源自 0x72 DungeonTileset II 的 CC0 像素帧。用户确认的写实 2.5D 版式图是视觉目标，并非本次 v0.3 实机画面。后续需合法取得与制作统一写实人物/怪物 spritesheet、完整地牢房间模块及装备纸娃娃插画，再作实机视觉验收。
- 未验证真机 iOS/Android 长时间帧率、连续 5 区域全通关、不同天赋组合平衡、背包装满情况下死亡、Boss 攻击前摇路径规划与无障碍细节。
- GitHub Pages 托管纯静态游戏，没有服务器、多人账户与云存档。正式商业化需要重新审查美术权利、资产分发方式及数据服务。

## 视觉 A 方向后续验收门槛

1. 真实游戏截屏（非概念图）里的角色比例、场景斜视感、石造立面、雾、火光、阴影与已确认稿同方向。
2. 地图必须有可辨识的五个主题，不得只用色调不同的重复地砖；拼接房间须与碰撞一致。
3. 角色的移动、受击、施法与至少六种敌人的动画方向统一，且不会用付费素材替代合法授权。
4. PC 人物纸娃娃需显示实际装备外观变化；手机端背包和技能页适配触屏。
5. 正式纳入可发布版本前，先给出真实游戏截图的比较表；不要将宣传原画当成实机截图。
