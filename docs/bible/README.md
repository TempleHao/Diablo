## 先读故事

灾难“断昼”之后，赫烬大陆用余烬炉抵御吞噬身份与边界的空潮。余烬能保存生命、记忆与魔力痕迹，但过度提取会消耗人的记忆。玩家是一名携灯出发的法师，从修灯匠诺娅所在的营地一路深入破损的炉网，逐渐发现司炉长伊瑟的集中控制方案确实有效，却把代价交给了无权选择的人。

五幕分别围绕生存、分配、保存、秩序和维护展开。最终战后的世界仍然需要修复，终局契约因此有持续调查和维护的理由。主线分支产生人物、营地和道路状态差异，各结局保持相同战力预算与终局资格。

|幕|地区|故事问题|对应玩法方向|
|---|---|---|---|
|一|灰烬边境|先救回一盏灯，再决定如何维持营地|基础施法、读招、拾取与第一套构筑|
|二|盐雾海岸|有限航路和庇护应如何分配|远程威胁、路线选择与资源稳定|
|三|镜霜高地|保存记忆是否等于让人继续活着|控制、失衡、地形与机关|
|四|星坠王都|有效率的秩序由谁承担代价|复杂敌群、装备比较与构筑取舍|
|五|无昼深渊|拒绝绝对控制之后怎样承担维护|综合Boss、结局与终局目标|

完整叙事、人物、35个主线任务、24个支线任务、对白样稿和任务状态见[第二卷](02-STORY-WORLD-AND-QUESTS.md)。

## 怎样使用这份纲领

先读01和02理解游戏要提供什么体验和故事，再按03—06查看完整玩法；要动手制作时读07和08。装备效果的具体计算归03，生成和制作归05；关卡合法性归04，风险奖励与在线模式归06。发生冲突按08的规则归属处理，避免出现两套同名算法。

完整设计包含合作、交易、赛季、排行榜等扩展，它们进入D4独立服务阶段。首个完整单人版为D3，先通过D1切片和D2系统验证。文中的内容数量是内容预算与样例库，真实制作仍需模型、场景、动画、音效、数据和试玩，不把策划表格行数当成现有库存。

后续修订保留版本、影响和验证依据。原先简短的[Demo设计草案](../GAME-DESIGN.md)作为历史文件留存，与本基线冲突时采用本基线。在线阅读页和完整Markdown由源章节生成，统计清单注明每章实际汉字、总字符、字节与哈希。

## 重新生成阅读文件

运行 `python3 -m pip install Markdown==3.11` 后执行 `python3 scripts/build-bible.py`，生成完整Markdown、阅读页与统计清单。PDF可另外安装Python Playwright和Chromium，再执行 `python3 scripts/export-bible-pdf.py`；Chromium默认路径为 `/usr/bin/chromium`，可用 `BIBLE_CHROMIUM_PATH`指定。游戏运行本身不需要这些文档制作依赖。
