# 第一卷：产品纲领、玩法覆盖与系统关系

> 本文是完整游戏的策划基线1.0，当前可运行Demo仍为0.2.0。文内“完整版本”指制作目标，“数值提案”指需要模拟和试玩校准的规则，不代表承诺工期、制作库存或已测耐玩时长。

## 1.1 产品定义与玩家承诺

《归墟》是一款以法师为首发职业、适合手机浏览器与电脑键鼠的原创3D俯视动作角色扮演游戏。玩家从一个将要熄灯的营地出发，探索五幕世界、理解怪物组合、收集有身份的装备，再通过技能符文、天赋和装备组合形成不同打法。剧情通关后，玩家使用秘境契约选择风险、地图与奖励方向，在专项Boss、远征和收藏目标中继续完善角色。

用户最优先要求有两个：第一次打开就能理解移动、施法、躲避与捡装备；长期游玩要能持续发现更好的组合、不同的刷取目标和新的挑战。产品成败不能由“装备品质颜色变多”或“总战力数字变大”判断。至少要有三种真实构筑差别、可学习的敌群反制、可规划的获取路径和可选择的挑战。

完整策划包含未来合作、交易、赛季和硬核，但这些需要服务端与额外内容维护；静态GitHub Pages原型不能自行承担可信排名和物品交易。单人基础必须先独立成立：没有队友、没有购买装备、没有每天签到，玩家仍然可以完成剧情、做出构筑、选择终局目标并有正常进展。

## 1.2 六项设计支柱

**支柱一：少量操作承载大量决策。** 完整触屏栏为免费主攻、两个主动技能、固定闪现和药水，共五键。深度放在技能行为、施法时机、目标顺序、构筑与地图选择上。新手只需先掌握移动和主攻；精英与Boss逐步要求使用控制和位移。配置界面有推荐路线与解释，熟练者可展开公式与标签。

**支柱二：一次刷取至少产生一种可解释进展。** 装备惊喜、材料积累、图鉴信息、专项目标进度、地图网络或收藏都可以成为进展，但不能给每种行为造一种货币。掉落概率、兑换与低风险入口共同形成目标路径；完全失败时提供失败原因与调整方案，不能用永久损失普通角色来拖长时长。

**支柱三：装备改变打法并形成取舍。** 底材、前后缀、孔、符文序列、独特效果和套装各有职责。稀有提供可优化的常规属性组合，独特负责行为改变，符文序列让普通底材也值得寻找。双手法杖与魔杖副手比较的是两个装备位的总预算，不能让玩家误以为单件数值高就一定升级。特效、持续伤害与生存不被假精确地折算成一个通用战力。

**支柱四：关卡和怪物共同提问。** 房间布局影响能否绕过前排、是否可以聚怪、怎样躲冲锋与远程预警。怪物家族不是同一AI换外观，而是群攻、近战、远程、支援与重击的组合。精英词条和地形机制受攻击调度与禁用组合约束；随机生成需要验证可达与正常走位可解。

**支柱五：世界能解释玩法。** 五幕分别讨论生存、分配、保存、秩序与维护。装备来源、怪物行为、机关和终局契约都有叙事身份。玩家做完一幕后看见营地、道路与人物状态变化。重复刷取是对不稳定炉网的调查与维护，不重复让同一个无辜家庭受难。

**支柱六：计划能够被验证与维护。** 每个系统有数据字段、边界情况、计量方法、测试和阶段交付。数值调优通过可重复种子、标准构筑与真实设备结果进行。没有做过的功能明确列为计划；没有测过的性能和时长明确列为目标。

## 1.3 核心循环、会话循环与长期循环

最小战斗循环是看见威胁 → 选择站位和目标 → 施放或保留技能 → 获得结果 → 判断下一步。它的即时反馈包括攻击命中、怪物硬直、危险预警、资源变化与掉落表现。动画、命中判定和伤害必须同一时间线，不能视觉上躲开却被服务器或旧状态扣血。

一局循环是选目标 → 配置构筑 → 选风险 → 进入模板关卡 → 做支路决策 → 完成Boss或事件 → 结算确定性进度和随机奖励 → 对比装备/打造 → 决定再刷还是休息。低风险常规掉落拾取即保存，风险附加奖励在成功结算时提交，区别在入口和结算页面说明。

长期循环是剧情与地区解锁 → 第一个不依赖极稀有物品的构筑 → 发现不足 → 为目标刷特定来源 → 调整属性与技能 → 解锁更难的契约或专项Boss → 尝试第二种打法 → 收藏、网络和远征目标。玩家永远应能回答“下一局为什么去那里”，而不是只被一个不断上升的推荐战力牵着走。

这些循环相互联系：一件改变冰霜碎裂的装备会使玩家考虑群怪更多的契约；一次支援精英导致失败，促使玩家调整主动技能而不仅增加伤害；完成海岸研究解锁一个可靠制作入口，帮助玩家为王都补足防御。任何系统如果不能进入至少一条循环，需要说明它的独立价值与维护成本。

## 1.4 对参考游戏的研究方法

本纲领参考稳定机制与设计意图，不是复制某个版本的全部具体数值，也不宣称覆盖《暗黑》与《流放之路》历年每个赛季的所有临时内容。研究资料分为官方现行介绍、旧官方机制资料和开发期说明。旧资料适合理解结构，不能未经核实就当2026版本数据库。

《暗黑II》的官方装备说明涉及前后缀、词条互斥与稀有物品组合；官方符文之语说明强调底材、孔数与顺序共同决定结果。这两点支持本游戏保留“找合适底材”和“组合有条件”的价值，但我们把制作预览和错误检查放在确认前。[装备说明](https://classic.battle.net/diablo2exp/items/magic.shtml)、[符文组合说明](https://classic.battle.net/diablo2exp/items/runewords.shtml)

《暗黑II》的方块与雇佣兵资料分别展示了持久制作工具和单人辅助伙伴的设计空间。本游戏把合成/配方/分解集中到余烬工坊，随从采用独立预算与明确定位，不让它偷偷成为第四条完整玩家职业。[合成工具资料](https://classic.battle.net/diablo2exp/items/cube.shtml)、[雇佣兵资料](https://classic.battle.net/diablo2exp/basics/hirelings.shtml)

《流放之路》的官方介绍描述了技能辅助改变技能行为、关键天赋改变玩法，以及地图词条连接挑战与奖励。这为本游戏的技能符文、关键天赋和秘境契约提供设计参考；我们的变体槽、天赋规模与货币体系需要适应手机上手成本。[游戏机制](https://www.pathofexile.com/game)、[物品机制](https://www.pathofexile.com/item-data)

暴雪的怪物家族设计说明展示了不同战斗角色搭配产生站位与攻击选择；地下城开发说明展示了模块环境与布局共同构建随机场景。我们据此制定敌群职责、房间模板、地图可达校验和美术可读性要求；这些文章是历史开发说明，并非对最终版本所有行为的保证。[怪物家族](https://news.blizzard.com/en-gb/article/23308274/diablo-iv-quarterly-updatefebruary-2020)、[地下城模块](https://news.blizzard.com/en-us/article/23788294/diablo-iv-quarterly-updatemarch-2022)

本稿中的故事、技能、物品、怪物、配方与契约内容属于原创提案；写清设计理由不等于已经证明有趣。官方来源支持参考机制事实，具体提案由本项目的约束与目标推导，再通过测试验证。

## 1.6 哪些系统必须一起完成

构筑闭环需要03的技能标签和公式、05的词条与独特、04的真实敌群以及07的比较界面一起成立。如果只完成装备数据而没有不同敌群，玩家无法体验安全性和清群差别；如果只完成技能特效而没有资源与触发边界，会出现一个无代价最优按钮；如果只完成公式而界面不解释标签，新手仍无法判断物品。

刷取闭环需要04提供具体来源、05提供可追求物品和材料、06提供选择风险与保底进展、07提供入口与结算。故事闭环需要02任务状态、04关卡机关、07场景状态与存档共同验证；任务文案写“城市获救”而场景没有改变，不算完成。

技术基础也有依赖。多人交易需要服务端物品实例ID、权威掉落、原子转移和恢复；不能把现有localStorage导出存档直接导入可信线上经济。赛季需要版本化内容、统计、迁移和维护人员；不能在没有长期维护计划时每三个月承诺一整幕。任何在线扩展先以独立验收通过，再连接永久角色。

## 1.7 内容规模与可扩展预算

本稿给出五幕故事、完整法师技能目录、三路线样构筑、数十种房间与怪物、专项Boss、底材/词条/独特/套装/符文实例、终局挑战与UI规范。目录数量表示已策划的候选内容，只有完成数据、资产、逻辑、测试和真实设备体验后才能计为已制作内容。

第一轮垂直切片只从目录选一个可以展示全部核心依赖的小组合：第一幕局部、两路线、几种怪物、少量房间、一个主Boss与一个精英事件、六槽过渡装备、少量真实词条、一次打造和一次风险奖励结算。它的目标是验证后续扩展有基础，而不是把削减后的内容当最终游戏。

完整单人版本的内容预算要同时计算资产与行为差异。一个“新怪物”至少有区别于已有角色的识别、决策或组合位置；一种“新装备”至少提供新选择、来源身份或制作价值；一个“新房间”至少提出不同走位/目标/机关问题。只改颜色、名字和伤害系数可以是变体，不能全部算作新的独立内容。

## 1.8 如何判断“易上手而耐玩”

易上手检验来自陌生玩家：能否在没有口头解释下完成移动、第一次击杀、躲避预警、换装与退出保存；能否说出主线目标；第一次面对三个装备词条时是否知道哪个适合当前技能。不能只让熟悉设计的人试玩。

耐玩检验来自持续选择：相同装备预算下三路线的清群、单体和生存是否不同；玩家是否能主动选刷取来源；连续几局未出目标时是否有可见进展；一个失败是否促成调整技能、站位或属性；第二种构筑是否改变对地图和怪物的理解。观察多次会话而不是只统计一次首通时间。

数值团队记录分布而不是只记录平均：构筑入门所需成功次数、目标掉落的长尾、Boss死亡原因、各词条保留率、重铸成本、玩家主动退出与设备帧时。发现某个系统失败时，要能定位是解释不足、内容同质、奖励不公、操作困难还是数值失衡，再改对应机制。

不能用理论组合数、总字数或装满表格来证明完成策划。本文的作用是让这些问题可被明确制作与验证；它需要随着实现结果更新，保留决定和变更记录。
