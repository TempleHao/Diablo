# 《余烬纪事 2D》美术方向 A：生产计划与质量门禁

状态：开发中的视觉基准；**不是已经完成的美术交付**。
基线：用户确认的写实、斜俯视（2.5D）暗黑幻想画面，参考此前的地图、角色、怪物、装备、PC 和移动端 UI 样稿。样稿属于生成的概念图，不能作为实机截图或未拆分贴图直接用于游戏。

## 截至 2026-10-13 的实际差距

v0.3 实机使用 0x72 DungeonTileset II（CC0）像素图集，角色大头比例偏卡通；地砖可读但空间纵深、立面建筑、五区域素材差异不足；13 装备栏目前仅以文字标签呈现，角色纸娃娃外观不会随着装备变化；移动版 UI 仍有小字号和遮挡风险。任何新增照明效果都无法单独弥补角色模型/精灵缺位。

## 不可妥协的上线门槛

1. **资产可复用与授权可审计**：新增素材必须来自明确允许网页作品及仓库实际授权范围的来源，记录作者、许可、来源链接及具体使用文件。不能因为是私人项目就默认可以上传付费素材或商业 IP。
2. **五个区域清晰区分**：断昼前庭、遗弃监牢、余烬祭坛、渊底裂隙、失名者圣所要有不同地板、立面、障碍、饰物的组合，不能仅通过色调改变。
3. **人物与怪物风格统一**：灰烬法师、骷髅战士、弓手、教徒、瘟疫巨汉、蜘蛛、灰烬司祭使用兼容镜头角度与脚底定位的精灵。至少待机、移动、攻击、受击、死亡动画具有可重复验证的序列与不穿地的锚点。
4. **装备真实反映外观**：先实现武器、兜帽、胸甲、肩部至少 4 个高辨识部位的独立图层；人物纸娃娃和战斗精灵必须基于同一装备外观标识产生变化。
5. **与 PC/手机输入对应**：PC 1365×768 与触屏 390×844 实测画面，能看清玩家、敌人、怪物前摇、地图障碍和技能按钮。不能将桌面 UI 直接压缩为手机。
6. **视觉真实性**：PR 必须提交“同一浏览器、同一敌群、同一机位”之前/之后的游戏 Canvas 截图，注明模拟视口及实际使用资产；概念图只可出现在“目标参考”区。
7. **性能与游戏质量**：不得牺牲基本移动、碰撞、存档升级、装备词缀、全套技能或 3D 原版。CI 规则与 Chromium 桌面/手机测试通过。额外验证真实手机设备后才可宣称真机流畅。
8. **保守合并策略**：任一关键门禁不满足时保留 draft PR，不并入 main；Docs 同步记录卡点，不将自动化测试通过等同于艺术验收。

## 开发批次

- **ART-A-01：建档与参考对齐** —— 授权审查、分区域/分职业资产清单、尺寸与视角规范、当前实机截图对照、性能预算。
- **ART-A-02：地图与立面** —— 一间完整的斜视入口厅、一条监牢长廊、一间仪式厅、洞窟段；真实素材贴图拼接且碰撞一致，做首张“无 UI 场景效果对照”。
- **ART-A-03：角色、怪物及动画** —— 法师 + 六类首章敌人的统一八方向或适当方向帧动画，攻击/施法/受击和死亡序列，真实战斗截图审查。
- **ART-A-04：纸娃娃、道具与技能面板** —— 装备图标多样性、至少四种可见换装部位、词缀展示及手机分栏。
- **ART-A-05：整合实测** —— 既有 13 槽、装备词缀、7 技能、五区域的集成回归；真实手机稳定性和首章完整通关体验测试。
